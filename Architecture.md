# SAMA-VIDHANA — System Architecture

## 1. Architecture Overview

SAMA-VIDHANA is an AI-powered civic and legal information system based on:

* Natural Language Processing
* Document Processing
* LangChain
* Retrieval-Augmented Generation
* Embeddings
* Vector Search
* Mistral 7B
* Government and legal datasets

The system accepts either a natural-language query, a document, or both, retrieves relevant information from its knowledge base, and generates a structured response.

The frontend follows a **Minimalism UI architecture**, keeping the interaction focused on the citizen's problem and the information generated by the system.

# 3. Frontend Architecture

The frontend uses a **Minimalism UI** design philosophy.

The purpose is to keep the interface clean and prevent the complexity of the underlying AI/legal system from being transferred to the citizen.

The main interaction area contains:

* Chat interface
* File upload
* User prompts
* Conversation context

The response area presents:

* Rights
* Eligibility
* Benefits
* Risks & Limitations
* Sources

The interface should prioritize:

* Minimal visual clutter
* Clear hierarchy
* Readability
* Simple interaction
* Easy document upload
* Clear separation of input and output
* Accessibility

# 7. Knowledge Base Pipeline

The source information is processed before entering the retrieval system.

```text
Source Websites
      ↓
Data Collection
      ↓
Cleaning
      ↓
Text Extraction
      ↓
Chunking
      ↓
Metadata Creation
      ↓
Embedding API
      ↓
Vector Database
```

Each chunk can contain metadata such as:

* Source
* Document title
* Section
* Category
* Date
* Scheme
* Law
* Source reference

---

# 8. Embedding Architecture

The embedding layer converts textual information into vector representations.

```text
Legal / Civic Text
       ↓
Embedding API
       ↓
Numerical Vector
       ↓
Vector Database
```

The user's query undergoes the same process:

```text
User Query
    ↓
Embedding API
    ↓
Query Vector
    ↓
Similarity Search
```

The vector search identifies semantically relevant information even when the user's wording differs from the source wording.

# 10. LangChain Architecture

LangChain is used as the orchestration layer connecting the AI components.

The planned pipeline is:

```text
User Input
    ↓
NLP
    ↓
Query Processing
    ↓
Retriever
    ↓
Relevant Documents
    ↓
Context Assembly
    ↓
Prompt Construction
    ↓
Mistral 7B
    ↓
Output Processing
```

LangChain coordinates the flow between retrieval, context construction, prompting, and model generation.

# 12. Mistral 7B Architecture


The model generates the final response based on the supplied context.

# 14. Rights Component

The Rights component identifies potentially applicable civic or legal rights.

It answers:

> **What rights may apply to this situation?**

The response should be generated from retrieved information rather than relying exclusively on the language model's internal knowledge.

---

# 15. Eligibility Component

The Eligibility component determines which requirements may apply.

It compares the user's available information with retrieved requirements.

```text
Retrieved Requirement
        +
User Information
        ↓
Eligibility Analysis
        ↓
Satisfied / Unsatisfied / Unknown
```

The system should distinguish between known and unknown information.

---

# 16. Benefits Component

The Benefits component identifies what the citizen may be able to receive, claim, request, or do.

Depending on the situation, this may include:

* Government benefits
* Legal remedies
* Applications
* Complaints
* Appeals
* Citizen services
* Recommended actions

---

# 17. Risks & Limitations Component

The Risks & Limitations component identifies factors that the citizen should consider before taking action.

It can include:

* Missing information
* Legal exceptions
* Jurisdictional differences
* Documentation requirements
* Deadlines
* Possible consequences
* Uncertainty
* Limitations of AI-generated guidance

---

# 18. Source Grounding Architecture

Source grounding is used to connect generated information with the knowledge retrieved from the system.

```text
Generated Claim
      ↓
Retrieved Context
      ↓
Source Chunk
      ↓
Original Source
```

The frontend can expose the source information to the user.

This provides transparency and allows the citizen to verify the underlying information.

# 20. Future Reinforcement Learning Layer

Reinforcement Learning is currently being considered as a possible future component.

It is not a mandatory dependency of the initial SAMA-VIDHANA architecture.

If implemented, it could potentially be used for:

* Improving retrieval
* Optimizing response quality
* Learning from user feedback
* Ranking retrieved information
* Improving system efficiency

The initial architecture therefore keeps RL as an optional extension.
